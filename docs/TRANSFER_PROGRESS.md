# 転送プログレス

送信開始から700ms以上続いた場合、既存のレスポンス欄に進捗バーを表示する。短い要求では遅延表示のタイマーを解除し、完了後にバーを出さない。エディターや送信ボタンの位置は移動しない。

- アップロード中: ブラウザからMiniPostへ保存確認できた添付合計バイト数と割合。
- 送信先へ転送中: バックエンドが送信先ソケットへ書込みを完了した本文バイト数と割合。multipartは境界・フィールドも含む。送信先アプリケーションでの処理完了を表すものではない。
- 応答待ち: 本文転送後は割合を消し、不定進捗へ切り替える。アップロード100%を要求全体の成功とは扱わない。
- 停止中、送信前スクリプト、受信後処理は段階名で表示する。最終応答・エラーは既存のレスポンス表示が担当する。

進捗はリクエストIDと送信試行ごとに保持し、ワークスペース・変更履歴へ保存しない。選択切替は他のリクエストの進捗を表示しない。前の試行の遅れたコールバックは次の送信に反映しない。

大容量の分割転送・ディスク経由転送を維持する。追加GETは最大1本ずつ、400ms間隔、1回2秒の上限。進捗取得失敗で本体送信を失敗・自動再送させない。取得できない割合は推測せず不定表示にする。停止・送信完了時にはGETとタイマーを解除する。

バックエンドは作成応答の `progress: true` で取得機能を通知する。古いバックエンドでは追加GETを行わず、送信先への段階を不定表示する。GET `/api/uploads/{token}/progress` は同一オリジン確認・no-store応答・読取専用。ファイルI/Oとは別の短いロックを使い、ポーリングではアイドル期限を延長しない。転送終了後にトークンが消えることは正常で、最終結果は本体要求で判断する。

`tests/ui_transfer_progress.py` は通常HTTPのChromiumで32MiB実ファイルを送信する。ネットワーク速度制限と実受信側の待機で各段階を観測し、サイズ・SHA-256、320px表示、別リクエストへの切替、停止・再送・失敗・短時間要求を確認する。既存384/512MiB検証も同じワークフローで引き続き実行する。
