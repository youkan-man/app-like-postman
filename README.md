# MiniPost / app-like-postman

Pythonバックエンド経由でHTTPリクエストを送る、Postman風のローカルワークベンチです。フロントエンドのビルド、外部CDN、Python追加パッケージは不要です。

## 起動

```bash
docker compose up -d --build
```

`http://localhost:8080` を開きます。停止は `docker compose down`。送信先には到達可能なAPIのURLを直接指定します。Python単体では `python app.py` で起動でき、`HOST` / `PORT` 環境変数で待受を変更できます。

追加のネットワーク設定は不要です。hostネットワーク、固定サブネット、extra_hosts、localhostの接続先切替は使用しません。URLのホスト名・ポートへそのまま接続します。

## ワークスペース

左にコレクション・環境・送信履歴・リレーションを表示します。選択カテゴリに対応する編集ページをメイン領域に開き、リクエストは選択中の1件だけを編集します。クエリ・ヘッダー・認証・本文・通信設定・スクリプトは、フラットな余白と左揃えのまま見出しから開閉できます。開閉状態はブラウザに保存し、入力値は閉じても維持します。開いたリクエストを上部に溜めるタブ列は設けません。設定カテゴリ・レスポンス表示・サイドバーのページ切替は使用できます。「すべて」では現在の余白のまま各設定を折りたためます。右上の分割ボタンで、広い画面ではリクエストとレスポンスを左右に並べられます。境界のドラッグ、または境界にフォーカスして矢印キーで表示比率を変更できます。サイドバーの開閉・幅、分割方向・比率、レスポンスの折り返しはブラウザに保存します。

**＋ 新規** と左の **＋** は選択中のカテゴリに応じた追加メニューです。コレクションではリクエスト・フォルダー・コレクション、環境では環境・変数、リレーションでは定義・ステップを選びます。送信履歴は送信時に自動追加されるため手動作成しません。右クリック／**⋯** の追加は、コレクション・フォルダーならその配下、リクエストなら同じ階層の指定位置（前／後）に挿入します。変数行・リレーションのステップにも前後への追加があります。

**環境** を選ぶと、環境変数・Globals・一次変数をメインページで編集できます。環境のドロワーは使用しません。入力は自動保存され、適用中の環境は上部セレクターと同期します。コレクション・フォルダーの変数／認証設定と変更履歴は従来の編集パネルで開きます。複製・設定コピー／貼り付け・変数行コピーは右クリック／**⋯** から操作します。リクエストの **環境変数を抽出** は `{{名前}}` を一覧化し、新規または既存環境へ取り込みます。既存値の上書きは明示的な選択です。

本文は大きなネイティブテキストエリアで編集し、JSON・JavaScript・XML・HTML・GraphQLに応じたハイライトを表示します。選択・コピー・IME・Undoはテキストエリアの標準操作を使用します。狭い画面で送受信を上下表示するときも本文領域を確保し、必要に応じてワークベンチを縦スクロールします。

- コレクション・フォルダー・リクエストの作成、名前変更、複製、削除、検索、日時付き送信履歴からの再編集。
- ParamsとURLの双方向編集、Headersの有効／無効、Authorization、Body、URL変数、送信前／受信後スクリプト、Settings。
- 環境切替、Globals／コレクション／環境／URL変数、`{{variable}}` 展開、コレクション・フォルダーからの認証継承。
- レスポンスのPretty／Raw／Headers／Cookies／HTML Preview、検索、コピー、バイナリを含む保存、HTTPステータス・時間・サイズ。
- 選択したリクエストの送信とレスポンス保持、ダーク／ライト切替。`Ctrl/Cmd+Enter` で送信、`Ctrl/Cmd+S` でコレクションへ登録。右クリック／操作メニューから保存済みリクエスト・下書き・送信履歴の送信／再送信もできます。レスポンス表示形式はレスポンス内のタブで切り替えます。

**ローカル保存が基本です。** 下書き、変更履歴、送信履歴、コレクション、環境、Globalsは同じブラウザ・同じオリジンのlocalStorageに編集後自動保存されます。コレクションに登録済みのリクエストも変更時に保存されます。

**サーバー保存は明示操作のみ**です。上部の **データ管理 → サーバーへ保存** を実行したときだけ全体のJSONを `/api/workspace` に書き込み、**データ管理 → サーバーから読込** で復元・追加を選びます。サーバーへの自動同期、起動時のサーバー自動読込はありません。Docker Composeでは名前付き永続ボリューム `minipost-data` の `/data/workspace.json` に保存します。Python単体では `.minipost/workspace.json`、`MINIPOST_WORKSPACE_FILE` で保存先変更も可能です。

**データ管理 → 全体エクスポート** はコレクション・環境・Globals・下書き・送信履歴・設定別変更履歴・リレーション定義／実行ログ・レイアウトを単一JSONで保存します。上部「インポート」ではこの全体JSONの置換／追加、または従来のPostman JSONの個別・複数インポートを選べます。ファイルエクスポートとサーバー保存は別の操作です。

**認証情報はブラウザのlocalStorageに平文で保存されます。明示的にサーバー保存した場合、同じ情報がサーバーのJSONにも平文で含まれます。** サーバーにはユーザー認証や分離、クラウド同期はありません。共有PCやLAN公開時はアクセスを適切に制限してください。未信頼ネットワークへそのまま公開しないでください。

## 設定ごとの変更履歴

リクエスト・環境・Globals・コレクション・フォルダー・リレーションの各メニューから **変更履歴** を開けます。入力後の自動保存時に日時・変更項目・設定値を記録します。単に開く／選択するだけでは記録しません。過去の版を復元すると復元自体も履歴に追加し、自動送信はしません。履歴は同じブラウザ・同じオリジンに保存され、設定ごとにJSONエクスポートできます。認証情報を含む履歴も平文で保存されるため扱いに注意してください。

## Postmanからインポート

上部の **インポート** からJSONファイルを複数選択、フォルダーを選択、またはJSONを貼り付けます。ZIPは展開してから選択してください。

| 入力 | 対応 |
| --- | --- |
| Collection v2.0 / v2.1 | フォルダー階層、リクエスト、変数、認証、Body、説明、イベント・例などのメタデータを保持 |
| Environment / Globals | 名前・値・有効／無効を取り込み、環境を切り替えて使用 |
| `collections` / `environments` / `globals` を持つJSONダンプ | まとめて取り込み |
| Postman APIの `collection` / `environment` ラッパー | 内側のデータを取り込み |

展開したdata dumpの `archive.json` がCollection／EnvironmentのID一覧だけを持つ場合は、索引として警告を表示して読み飛ばします。**索引だけでは設定を復元できません。同じフォルダーのCollection／Environment本体のJSONも一緒に選択してください。** 壊れたJSONや不正なリソースを黙って無視する動作ではありません。

個別のPostmanインポートでは、同名でも別コレクション・別環境として追加し、既存データは上書きしません。全体バックアップでは読み込み前に置換／追加を選びます。複数ファイルの解析に失敗した場合は、その取り込み全体を反映しません。Collection／Environmentは再エクスポートできます。Collection v2.0のオブジェクト形式とv2.1の配列形式の認証属性を扱い、編集後も宣言されたスキーマに合わせて出力します。

送信できる認証は **No Auth / Basic / Bearer / API Key**、および取得済みアクセストークンを設定したOAuth 2.0です。Bodyはraw（JSON・Text・XML・HTML・JavaScript）、x-www-form-urlencoded、form-data（ファイル含む）、binary、GraphQLに対応します。無効行は送信せず、重複クエリ・ヘッダーを保持します。未設定・循環変数は送信前に表示します。

**Postman完全互換ではありません。** インポートされたPre-request / Testsは参照用として保持し、勝手に実行しません。スクリプト欄の「編集欄へコピー」で取り込み、対応するAPIを確認してから実行してください。OAuthトークン取得フロー、Digest等の追加認証、Postman Collection Runnerとの互換、WebSocket/gRPC、Cookie jarの自動再送、クライアント証明書・プロキシ・Postmanアプリ全体のPreferences移行は未対応です。インポートしたファイルパスからローカルファイルは自動取得せず、送信時に選び直します。未対応の認証・Bodyモードは黙って別方式へ置換せずエラーにします。

既存の自己署名HTTPS向け動作を維持し、**TLS証明書検証は初期状態OFF**です。SettingsでONにできます。リダイレクト追従とTimeoutも変更できます。Timeoutの0は無制限です。Cancelはレスポンスの受信を止めますが、既に送信済みのサーバー処理を取り消すものではありません。

## 一次変数と受信後の抽出

一次変数は `{{名前}}` で参照し、同名の環境変数・コレクション変数・URL変数より優先します。環境ページ内の **一次変数** で編集・削除できます。環境変数とは別に、同じブラウザタブのsessionStorageへ保存するためページ再読込後も使用できますが、全体バックアップには含めません。

一度受信したレスポンスは同じタブのセッションに保持します。**一次変数に抽出**、またはリクエストの **レスポンスから一次変数を抽出** で、HTTPステータス・ヘッダー・Cookie・JSON本文などを選択できます。例: `/status`、`/headers/content-type`、`/body/items/0/id`。抽出先の変数名を指定し、その場で取り込むか、以降の受信時の自動抽出ルールとして保存します。自動抽出の欠損時動作は「前値維持／空文字／エラー」から選べます。受信データと一次変数には機密値が含まれる可能性があります。

## スクリプト

各リクエストの **スクリプト** で「送信前／受信後」を編集します。`vars.get/set/unset`（`pm.variables`）、`pm.environment`、`pm.globals`、`response.body`、`response.headers`、`pm.response.json()`／`text()`、`pm.test()`、`console.log()` を使用できます。Postmanの全APIや外部ライブラリーに互換対応するものではありません。

```javascript
// 送信前: 一次変数を設定
vars.set('requestId', 'example-001');
// 受信後: JSON本文の値を次のリクエストへ渡す
vars.set('accessToken', response.body.access_token);
```

送信順序は「送信前スクリプト → 変数展開 → HTTP送信 → 自動抽出 → 受信後スクリプト」です。単独のスクリプト実行ボタンはHTTPリクエストを送信しません。実行はDOM・アプリのストレージ・ネットワークへ直接アクセスできない分離Workerで行い、値の変更は公開APIを通して反映します。制限時間の0は無制限です。上部の **実行を停止** で停止できます。失敗したスクリプトの変数変更は反映せず、受信後の失敗でもHTTPレスポンスは残します。

## リレーション

既存の保存済みリクエストまたは下書きを参照するステップを並べます。ドラッグ、上下ボタン、右クリックで並べ替え・前後への追加・複製ができます。各ステップの開始前待機、反復回数と間隔、全体の反復回数と間隔を設定します。ステップの反復完了後に、最終レスポンスの要素または一次変数を比較し、次のステップ・指定ステップ・その回の終了へ分岐できます。比較値にも `{{変数}}` を使用できます。

定義とリクエストは開始時にスナップショット化し、環境は開始時の選択を使用します。一次変数はステップ間で共有します。HTTP／スクリプトのエラーで停止するか続行するかを指定でき、実行結果には順序・HTTPステータス・時間・分岐・エラーを記録します。最大実行数の0は上限なしです。循環する分岐も **停止** で中断でき、待機中も操作できます。停止は既に送信したサーバー処理をロールバックしません。

## 検証

アプリ側の `MiniPost verification` が回帰試験・実ブラウザ・UI操作と画面撮影・Dockerを実行します。Gatewayとの結合試験はGateway側で別実行します。ブラウザE2Eの画面は実HTTPのEchoサーバー応答であり、Gatewayの画面ではありません。物理COM/USBの試験は含みません。実行方法・試験範囲・Artifactsは [TESTING.md](TESTING.md) を参照してください。
